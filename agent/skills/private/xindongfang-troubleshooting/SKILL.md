# 新东方问题初筛

## 定位

这是新东方业务场景的前置路由 Skill。它根据客户问题类型和 Argus 现场证据，判断是否命中新东方的已知特殊集成或处理规则，然后给出：

- 已确认的业务场景和问题类型；
- 需要通过 Argus 核验的字段、Event、Counter 或媒体方向；
- 命中条件后的配置建议和内部参考链接；
- 条件不满足或没有匹配类型时，转交 `agora-wecom-support-assistant` 继续处理。

明确满足本 Skill 处理条件的问题，直接给出专项结论和具体处理方案，在对应结论后单独注明“结论来自新东方专项SKILL。”。需要 Event/Counter 的分支先展示实际关键证据；仅依赖已明确平台、症状或使用场景的分支简述已确认条件，不为凑证据强加在线查询。来源标记不代替必要取证，也不用于未命中的问题或通用支持的独立结论。

所有明确命中的专项分支统一按“必要证据或已确认条件 → 明确结论及来源 → 处理方案 → 复测 → 已核验的 Argus 链接（如有）”答复。默认不附来源/模板未核验、根因未确认、方案仅供参考或不能保证恢复等免责声明；这些事实边界作为内部判断约束执行，不逐条转述给用户。影响操作的实际冲突、必要证据缺口、操作范围和先后顺序仍需明确说明，不能以精简回复为由隐藏。

本 Skill 被加载后，先完成客户初筛；明确命中的部分由专项直接给结论和方案，需要继续调查的部分再进入通用支持。可以提前加载公共 Argus Skill 取证，但不跳过本 Skill 的条件判断。目录名或文件排序本身不提供执行优先级，应由外层服务为新东方用户显式绑定或预加载本 Skill。

本 Skill 不调用配置下发接口，不修改客户配置，不把历史配置链接当作已执行结果。Argus 查询必须交给 `argus-online-channel-troubleshooting` 的只读 REST 流程。

进入本 Skill 的问题一律默认是新东方客户问题，不再判断或追问客户归属。附件中的【原因】是既有排查方向，不是本次问题的已确认根因。

## 先执行本地分类

每条新问题先执行 `scripts/classify_issue.py`，不要仅凭大模型自行选一个分类。脚本只读取问题和本地规则、返回分类 JSON，不联网、不读取凭据、不查询 Argus，也不执行任何配置。

用文件工具把本次用户问题原文写入单独 UTF-8 临时文件，将其视为数据；不要把用户原文直接拼入 Shell 命令：

```bash
python3 <本Skill目录>/scripts/classify_issue.py --input <问题文件绝对路径> --output <分类结果绝对路径>
```

要求 Python 3.10+，仅使用标准库；若 `python3` 不满足版本要求，选择目标环境已提供的兼容解释器。也支持标准输入。可选 `--context <JSON文件>` 只传此前已确认的 `channel_name`、`teacher_uid`、`student_uid`、`user_uid`（均为字符串）和 `platform`；不要把旧问题全文或猜测的身份作为 context，当前消息中新给出的带标签身份优先。明确换教室时不继承旧角色 UID 和平台；换问题用户时不自动继承旧对象信息。平台必须能关联到同一目标 UID 才继承，不能单独传一个旧平台就用于新对象。检查 `identity.context_inherited_fields/context_warnings`，不把被跳过的旧值补回。

读取分类结果后：

- `matched`：按 `categories` 的 `reference_section` 读取下面的处理矩阵，继续核验实际平台、SID 和指标。多类别分别处理，不只选数组第一项。
- `ambiguous`：查看 `review_reasons`、每项 `route/pending_checks`，结合原文做补充语义判断或交给通用支持取证。摄像头不显示、远端看不到而本地正常，不等于已证实摄像头采集失败；优先用 Argus 获取可查信息，不机械地立即追问。
- `unclassified`：携带 `fallback.intents` 和原问题进入 `agora-wecom-support-assistant`。普通卡顿、网络设备检查、回放、闪退和互动录音均有明确通用路由；未匹配不代表没有故障。
- `fallback.required=true` 时，在处理明确分类的同时保留未覆盖需求。`fallback.evidence` 保留通用需求的原文位置、对象和媒体来源，不能因另一项专项命中就忽略独立的网络或设备检查。`needs_clarification` 是语义复核标记，不是必须询问用户的指令。
- 脚本报错或不可运行：明确记下分类不可用，用原文做有限人工/模型初筛并继续通用支持，不假称代码已命中。

脚本按否定、恢复、回放范围、多对象与媒体方向做有界规则识别；仅抑制同一局部范围、同一对象和音源、原文位置重叠的重复症状，不跨对象删分类。播放/回放场景可继承到紧邻的一条省略表达，遇到换对象、换音源、换问题、空行或不相关语句即停止；不是无限跨句继承。URL 目标被遮蔽，Markdown 链接文字保留，`url_boundary_uncertain` 表示裸链接与中文粘连无法确定边界，须复核原文但不要输出链接签名。它不能完整理解所有自然语言；模型只负责复核歧义、纠正有依据的误判、补充规则未覆盖表述，不得悄悄改写脚本结果。复核时保留原分类、原文依据和更正原因。用户一句“帮我配置”不等于授权实际下发配置。

规则存于 [references/classification-rules.json](references/classification-rules.json)，分类字段、50 条素材覆盖和测试命令见 [references/classification-guide.md](references/classification-guide.md)。

## 新东方固定背景

- 根据新东方集成约定，“课程 ID”“课次 ID”“讲次 ID”“教室 ID”原样作为频道名候选传给 `search-calls --channel-name`，不因全为数字就传给 `--channel-id`。这里业务口述的 channelid 不等于 Argus 返回的数字 `channelId`；后者只从通话结果中读取。“老师 ID”“学员/学生 ID”及角色后的括号数字分别作为对应 RTC UID 候选；仅写“用户 ID”时指问题用户 UID。姓名、学员号和账号中的数字不能直接当作 RTC UID。拿到查询结果后仍需精确核对实际 UID 和 SID；无标签独立数字只作频道候选，不无声升级为已确认频道。
- PC 端指 Windows 和 macOS；移动端指 Android 和 iOS。
- 附件约定只有老师 PC 端屏幕共享，屏幕共享 UID 是 `1006`；屏幕共享使用放大镜自采集，音频采集仍走 Agora loopback。把 `1006` 作为共享流线索，并查询核对其真实 SID；不能用老师主 UID 替代共享流，也不能仅凭这个常量推断某次共享已经发生。
- PC 端用户使用自渲染。
- 录制可能是老师端用裸音频和屏幕截图自行合成，也可能是阿里云 H5 学生端入频道录制；不要默认这是声网页面录制。
- 附件约定 PC 老师通过清空 `onRecordAudioFrame` 数据静音麦克风，而不调用 `muteLocalAudioStream`，目的是保留 `startAudioMixing` 声音。SDK 静音位未置位不代表业务没有静音；采集/处理能量归零也不能仅凭该约定认定为用户主动闭麦，需核对同窗调用或业务操作。

按代码分类和必要的歧义复核结果读取 [references/new-oriental-rules.md](references/new-oriental-rules.md) 中的对应段落。该矩阵决定是否需要 Argus 查询；无需在线指标的已明确需求不必运行整套质量调查。分类 JSON 不包含根因或配置动作，不能跳过矩阵直接给规避方案。

## 输入整理

从用户消息或附件中提取：

```text
问题类型：旋转 / 模糊 / 摄像头黑屏或绿屏 / 回声 / 杂音 / 音量 / 无声 / 音画不同步 / 播放课件无声 / AirPlay / 断线重连
课程或教室 ID：原始字符串，作为 channelName 查询
老师 UID：可选
学员 UID：可选
问题用户 UID：优先作为 Argus 目标 UID
直播或上课时间：原始日期、时间、时区
平台和设备：Windows/macOS/Android/iOS，必要时补机型
现象范围：发送端、接收端、单向/双向、音频/视频、是否恢复
```

只追问当前分支所缺的最小信息，不要求一次补全整张卡。已有 Argus URL 时直接解析其中的 `callId` 和时间；已有日期与精确课程 ID 时，可按 Argus Skill 的整日定位规则查询；有明确频道但未给时间时，沿用该 Skill 的时间兜底，不一开始就阻塞在追问。确实无法定位时，优先问课程或教室 ID、问题用户 UID、发生日期和大致时段中的缺失项。

## Argus 初筛顺序

先按处理矩阵决定是否需要在线取证；仅依赖已确认平台、症状或使用场景的分支可直接按输出要求答复，不必为执行下列步骤而额外定位通话。需要在线证据或仍需通过 Argus 核验对象、平台时，再执行相应查询步骤。

1. 先运行分类脚本，整理问题类型、平台、媒体对象和方向；按上述映射使用客户已给字段，不要求客户重复证明含义。缺日期或平台不影响症状分类；需要该信息时再由 Argus 或最小追问补齐。
2. 按 `argus-online-channel-troubleshooting` 规则用代码把本地时间转换为 Unix 秒，并反向校验上海时间；禁止手算时间戳。
3. 没有 `callId` 时先按频道和时间执行 `search-calls`；如果没有频道线索，再按已知精确 UID 定位。模糊 UID 不能直接传给 API。
4. 用 `search-users --size 150` 获取完整用户列表，精确匹配目标 UID、平台、SDK 版本、SID、`joinTs/leaveTs` 和 `sender`。
5. 只选择覆盖问题时间的真实 SID。查询成功、覆盖充分且相关 Event 完全没有上报时，正向条件按不满足处理；Windows 摄像头的“无 cameraInfo”例外见矩阵。HTTP 错误、鉴权失败、超时、截断或 SID 不匹配属于证据不足，不能当作 Event/配置不存在。相关 Event 存在但未包含目标配置键，与整个 Event 缺失分开记录。ABTest 配置分支只检查 `params` 中目标配置键是否存在及其实际值，不使用其他事件元数据筛掉配置、改变分支、降低命中判断或阻塞建议。
6. 根据问题类型读取最小的 Event/Counter。需要网络质量时，再由 Argus Skill 查询 Counter/VoQA；需要配置状态时优先检查 `vosdk.abtest`；需要设备状态时检查对应 Device Event。
7. 命中明确处理分支时，需要在线证据的分支先展示实际 Event/Counter 证据，再直接给出结论，并紧接“结论来自新东方专项SKILL。”，随后给推荐配置内容和下发入口、操作顺序及复测标准。无需在线证据的分支简述已确认条件后直接给同样的专项结论和方案。完成当前分支后停止扩展无关调查；用户另有独立需求时继续处理，不因一项专项命中就结束整个任务。查到真实通话并核验目标 UID 时默认附 Argus 人工复核链接，不等客户索要；链接用法见 [references/evidence-and-response.md](references/evidence-and-response.md)。未命中、证据不足或没有对应类型的部分，加载 `agora-wecom-support-assistant` 在同一任务继续处理，复用已确认的身份、时间和结果，不仅输出“已转交”就结束。加载其他 Skill 的意义是读取并执行其工作流，不代表已经发送工单或通知人工。

加载公共 Skill 时，委托其完成本分支所需的只读取证。与客户处理策略有关的选择及专项结论的输出以本 Skill 为准；时间、身份、安全、指标解码和证据边界继续遵循公共 Skill。已命中部分不再交给通用支持重复生成另一套同类建议，不为重复确认该处理分支固定追加官网或百炼调查；遇到实际平台、SDK 版本或配置证据冲突时，先解决影响分支适用性的差异。未覆盖部分继续通用支持，不能把它的独立结论也标成来自新东方专项。缺少当前分支必需的公共 Skill 或 Argus 凭据时，明确报告阻塞，不捏造结果或改用配置链接代替查询。

## 输出要求

使用 [references/evidence-and-response.md](references/evidence-and-response.md) 的证据要求和模板。问题分类、对象、平台及处理条件均已核验时，直接输出专项结论和方案。需要在线证据的分支必须把关键证据展示在回复中，不能仅保留内部记录或只说“建议核实”“可能需要调整”；不需要在线证据的分支说明客户反馈或其他已确认条件即可，不输出空证据栏、不编造查询范围。分类脚本的 `matched` 不等于实际分支条件已满足。

```text
查询范围（实际查询时）：实际日期和时区、分析时间窗、教室、目标 UID、平台、SDK 版本；证据按 callId/SID 分组
证据（需要在线证据时）：Event 的实际名称、事件时间、相关详情；Counter 的实际 ID/名称/单位、数值范围、有效点数、异常区间和覆盖缺口
结论：明确查到的事实及命中的处理分支；有因果证据时再确认根因
结论来自新东方专项SKILL。
处理方案：操作目标和单机/机型范围、先后顺序、推荐配置内容、对应下发入口
复测标准：同设备同课件/场景下的具体观察项
Argus：已核验通话与用户的人工复核链接；多个 callId 分别按时间列出
```

具体执行要求：

- 用返回的真实数字、字段和值支撑结论。没有数据时明确写哪项未返回，不补造统计、Event 枚举、配置键或设备标识。与投诉相关的异常、恢复和冲突均需披露。
- 规则条件充分时直接说“已命中某处理分支，按下列步骤处理”，结论后单独注明“结论来自新东方专项SKILL。”。所有命中分支均不默认追加来源/模板、根因或方案有效性免责声明，不用“可能需要调整”“建议进一步核实”弱化已满足规则的方案。只表达该分支支持的结论，不补写专项未支持的额外原因，不把推荐写成已执行或复测成功；用户明确追问原因、版本或入口核验情况时再据实回答对应问题。
- ABTest 只按 `params` 中目标键和值判断，展示精简配置 JSON；其他事件元数据不参与判断，也不作为阻塞建议的依据。仅因果未闭合不应阻止给出已经满足规则的配置建议。
- 推荐配置必须附本 Skill 矩阵中的对应入口，不只给“调一下配置”。已有准确键名时展示 JSON；附件未给键名时用准确操作名称、数值和入口表达。优先单机，未明确要求时不扩大至机型或全网；UID 不直接当作设备标识。
- 无需改配置的分支也给明确结论及动作，例如“已存在旋转配置，值为 2；不再重复推荐旋转配置”，不硬凑下发链接。
- 条件不满足时给已查证据和具体缺口，再继续支持。查到真实通话且目标 UID 已核验时，即使最终未命中专项分支也附 Argus 链接；查不到或查询失败时不拼造链接。
- 来源标记紧接已命中的专项结论；必要条件缺失、未命中或只由通用支持得出的结论不加该标记。混合需求分别组织各项证据、结论与方案，不能用一个专项来源标记覆盖整份回复。
- 实际存在的模板命名冲突、配置值冲突、平台或版本不适用、故障时间无法对应等会影响执行或判断的事项必须保留；仅排除目标设备、先排除再单机配置、不停用全局规则等必要操作要求也必须保留。这些不是可省略的泛化免责声明。
- 只输出可核查的证据和结论，不输出隐藏推理。若渠道限制长度，保留关键证据、结论、所选配置入口及 Argus 链接，详细内容再按已具备的报告能力承载；不能只留一句模糊总结，也不能声称未实际完成的报告发布。

后续通用支持复用这份受理记录，继续按证据选择 Argus、SDK 日志、崩溃、RTM、RTSC、ConvoAI 或报告 Skill。新东方业务 H5 录制不是声网页面录制，不能仅凭“回放问题”路由到云录制任务查询；新的客户证据明确为声网云录制后再调整。一般卡顿、其他产品、未命中类型都不丢弃、不判成“无问题”，继续处理原始需求。

不要输出 API Key、Token、完整原始日志、客户内部凭据或未经核验的 Argus 结果。不要自动打开配置下发链接执行变更。

命中分支的回复附对应推荐配置入口；实际查到并核验通话和用户时默认附 Argus 链接，没有查询则省略该项，不为生成链接强加查询。它们是供有权限操作人使用的内部入口，不能绕过登录。直接提供矩阵中的对应入口，不默认附加来源或模板核验说明；内部仍不得声称未实际完成的链接核验。有配置建议时末尾说明“以上为推荐操作，本次未下发配置”；不要自动打开链接执行变更。完整 SID 可用脱敏前缀关联证据，URL 不携带 API Key、Token、设备 ID 或签名凭据。
