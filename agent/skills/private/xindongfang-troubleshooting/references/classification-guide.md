# 新东方分类脚本使用与素材覆盖

## 能力与范围

分类脚本是新东方 Skill 内的本地入口，不做客户归属判断。规则来源是《新东方问题汇总.doc》和 2026-10-27 提供的《新东方问题上报素材》50 条记录。运行不依赖模型、网络、API Key 或第三方 Python 包；输入为当前问题原文，输出是候选类别与路由，不是故障原因或配置建议。

未修改 HTTP 网关、Hermes 加载器或公共 Skill。Skill 加载后要求模型先运行脚本；如果部署需要所有请求强制经过分类，应由网关直接调用同一脚本，不能仅靠目录排序或本文件保证。

## 输入与输出

```bash
python3 scripts/classify_issue.py --input /tmp/xdf-question.txt --output /tmp/xdf-classification.json
```

`--input` 是 UTF-8 纯文本，未给时读取标准输入；上限 256 KiB。`--text` 仅用于本地固定测试短句，客户原文使用文件，避免 Shell 插值。`--output` 可选。`--rules` 默认为本 Skill 的 `classification-rules.json`。CLI 成功退出码 0、输入/规则/路径错误退出码 2；错误不输出用户全文和签名 URL。

可选 `--context` 文件只传已确认身份，例如：

```json
{"teacher_uid":"80000001","student_uid":"70000001","platform":"Windows"}
```

身份字段支持 `channel_name/teacher_uid/student_uid/user_uid`，以字符串保留，当前输入的明确标签优先于 context。平台接受 `Windows/macOS/Android/iOS/HarmonyOS/PC`；“电脑”只标 PC，不推定 Windows；鸿蒙不当 Android。已确认信息不代表 Argus 已验证，仍需精确匹配 SID。学员业务账号不能从尾部数字猜 UID。

context 先检查作用范围再填缺失值：

- 当前明确换教室，或当前教室无法与旧 context 关联时，不继承旧角色 UID、问题 UID 和平台。
- 同一教室换问题用户、变更已知角色 UID 或明确说“另一个学生”等时，不自动继承旧对象字段；仍可保留同一教室。
- 同一教室切换到已知学生时，可复用已确认的学生 UID，但不把原老师的问题 UID、平台套到学生。
- 平台只在 context 的 `user_uid`，或唯一已知 UID，能对应当前对象时继承。只传 `platform`、多个对象但平台归属未知时不继承。
- 普通同对象追问可继续复用已确认身份。`context_inherited_fields` 记录实际继承项，`context_warnings` 记录教室/对象变化及平台无法绑定等原因；不据此猜测被跳过的字段。

| 输出字段 | 含义 |
|---|---|
| `rule_version` | 规则版本，方便复现 |
| `status` | `matched`、`ambiguous` 或 `unclassified` |
| `categories` | 一个或多个候选问题，保留不同角色/UID/方向 |
| `matched_text/evidence/rule_id` | 匹配片段和规则编号，供模型对照原文复核 |
| `source_span/scope_id/media_source` | 原文位置、局部语句编号和媒体来源；用于限定去重范围 |
| `subject_uid/subject_role/direction` | 基于明确标签和局部语句的有限对象绑定；不确定时为空 |
| `reference_section` | 处理矩阵中应读取的标题 |
| `route` | `specialized_rule` 或 `general_support`；后者不能直接套专项配置 |
| `pending_checks` | 还需通过 Argus/原文复核的平台、方向、场景条件 |
| `identity` | 频道、角色 UID 候选和平台，未猜测 SID |
| `identity.context_inherited_fields/context_warnings` | 实际继承的 context 字段及未继承原因 |
| `excluded_matches` | 因否定、恢复、回放或更具体症状而排除的片段 |
| `fallback` | 是否继续通用支持以及未覆盖需求标签 |
| `fallback.evidence` | 通用需求的匹配原文、位置、对象、方向和媒体来源 |
| `needs_clarification/review_reasons` | 是否需要语义复核；不等于必须向用户发问 |
| `attachment_link_count` | 链接数量；不会请求链接或把签名参数输出 |

`source_span.start/end` 是用户原文中的字符下标，从 0 开始，end 不包含在区间内；不是字节或规范化后的下标。每个 `evidence` 保留自己的位置，重复文字出现在不同位置时不混用第一次匹配。`scope_id` 仅在本次结果内有效。`media_source` 为 `playback/microphone/loopback/replay/unknown`，只是词义范围，不是已经核验的实际 SDK 音轨。

## 50 条素材覆盖

`tests/reported-cases.json` 按原附件编号保留 50 条症状与预期输出。真实姓名、UID、教室 ID、监课链接和回放签名均已替换；素材只用于本地分类回归，不会触发线上查询。

| 结果 | 条数 | 素材编号 |
|---|---:|---|
| 明确匹配专项候选 | 35 | 1、3、5、6、8～12、14～21、23～25、28～29、32～34、36～38、40～44、47、50 |
| 摄像头采集/远端可见性待辨别 | 6 | 2、13、22、39、45、49 |
| 通用支持，不套专项配置 | 9 | 4、7、26、27、30、31、35、46、48 |

九条通用路由保留具体需求：回放为 4/30，普通卡顿为 7/26，网络设备检查为 26/27/35，闪退/异常退出为 31/46，互动录音为 48。一条可以带多个需求标签；“未分类”不代表忽略或无故障。

注意以下真实差异：

- 第 6/8/11/36 条均为课件播放分支；第 8 条进度条仍在走，也不能因为“无声”就当作麦克风问题。
- 第 12 条说话无声而触屏声音大，不是普通音量小；不直接推荐增益。
- 第 20 条共享电脑声音小而讲话正常，要保留 loopback/共享源与麦克风的区别。
- 第 2/49 条是远端不可见，不能直接确认发送端采集失败；本地正常作为后续证据保留。
- 第 31/46 条闪退或异常退出不是“频繁重连”的同义词，不能自动推荐 TCP Proxy。
- 第 38/44/45/47 条仅附回放链接，不把当前投诉改写为“仅回放故障”；第 4/30 条明确主诉回放异常则单独路由。
- 第 23 条提供的是学员业务账号，不能直接作为数字 RTC UID；第 17 条无标签课程候选需保留待核对状态。

## 匹配边界与维护

当前规则版本为 `1.1.0`。规则先做全半角、大小写和不可见格式字符规范化，保留原文位置映射，再遮蔽 URL 目标并按语句匹配：

- URL 后的中文逗号、句号等是正文边界；保留 Markdown 链接文字，识别目标地址内成对英文括号，不随意按英文逗号、问号和 `&` 拆 URL。中文路径与正文无分隔粘连时，返回 `url_boundary_uncertain`，保留复核需求，不把地址内容当作症状，也不输出签名。匹配不能跨越已遮蔽的 URL。
- 只在同一局部语句、同一对象、相同媒体来源及方向、原文位置重叠时抑制重复症状。同句连接不同角色时分别处理；同角色有明确不同 UID 时也分别保留。不再因为命中一个专项就全局删除网络/设备检查。
- `rtc-quality` 仅在它与专项是同一处症状时去重，例如“课件播放进度条卡住”中的“卡住”。“声音小；另外查老师丢包和设备情况”必须保留两个通用需求及 `fallback.required=true`。
- 课件播放或回放场景可延续至紧邻的一条相关省略表达，逗号、句号、单次换行不单独清空场景；出现新对象、新音源、明确新问题、空行、不相关语句或省略继承已用尽时停止。没有续接依据时不继承；显式再次提及播放会建立新的局部场景。
- `context` 不继承症状、根因或处理建议。常见否定/恢复由本地规则识别；复杂转述、引用、多角色省略和跨句纠正仍需模型复核，不能声称已解决通用中文语义理解。

不要为了提高“命中率”把通用素材强行塞进专项分支。调整规则时更新版本，并同时跑 50 条素材与额外反例：否定、恢复、多症状、方向、平台未知、签名链接、闪退/重连和未见表达。分类通过只代表路由符合这些用例，不证明根因或配置有效。

