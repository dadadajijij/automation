# 具体证据与处理结论

## 完全匹配与证据范围

只有症状、对象、实际平台和当前分支条件均已核验，才输出明确的分支处理结论。分类结果只决定先读哪条规则，不代替实际查询。满足条件后直接给明确结论和具体处理方案，在对应结论后单独写“结论来自新东方专项SKILL。”。

按处理矩阵决定证据要求，而不是所有问题都强制查 Argus：

| 情况 | 执行与输出 |
|---|---|
| 分支要求 Event、Counter 或设备事件，且实际结果满足条件 | 展示关键证据，再直接给专项结论、来源标记和处理方案 |
| 分支仅要求已明确的平台、症状或使用场景 | 简述已确认条件及其来源，直接给专项结论、来源标记和处理方案；不为凑证据强加在线查询 |
| 必需证据缺失、查询失败或存在未解决的适用性冲突 | 展示已查事实和具体缺口，继续调查；不写已命中，也不使用专项结论来源标记 |
| 专项未覆盖或条件不满足 | 带已查证据进入通用支持；其独立结论不标成来自新东方专项 |

需要在线证据时，回答按“查询范围 → 证据 → 结论及来源 → 推荐配置与入口 → 复测标准 → Argus 链接”组织，关键证据必须出现在回复中，不能只保留在内部或仅写“查到异常”。只展示支撑当前分支的必要事件字段和数值，不倾倒完整原始响应，不扩展无关调查。无需在线证据时，以简要已确认条件衔接“结论及来源 → 处理方案 → 复测”，省略未执行的查询范围和空证据栏。

下面的必需字段未返回时写明缺失，不把 null/无序列/未请求当成零。查询窗不是实际数据覆盖窗；URL 可能覆盖整段通话，正文仍应说明实际分析了哪一段。多个 SID 分开，不用后一次会话的数据替代故障时刻。单凭来源标记不能替代必要查询。

专项命中只结束当前已处理分支；`fallback.required=true` 或原问题中另有独立需求时，继续通用支持，不能遗漏。混合回复按问题分别列证据和结论，来源标记仅紧接命中的专项结论。已满足专项条件的部分不再由通用支持重复生成另一套同类建议；实际平台、版本或配置冲突影响适用性时，先核验冲突。

### 所有命中分支的对外表述

以下规则适用于全部明确命中的专项分支，包括旋转、模糊、摄像头、回声、杂音、音量、无声、课件播放、AirPlay 和重连中已满足处理条件的分支，不限于 FFmpeg：

- 保留必要证据、明确结论、“结论来自新东方专项SKILL。”、具体处理方案和复测标准；实际核验通话后附 Argus 链接。有配置建议时保留“以上为推荐操作，本次未下发配置。”。
- 默认不输出来源/模板免责声明，例如入口来自附件或模板未核验的附加说明；直接给对应配置入口，不声称已在线核验。
- 默认不输出未确认根因或泛化不确定性说明，例如不能凭当前配置确认下载失败、QP 高不等于硬编故障、不是唯一根因等附加说明。结论本身只写已命中的处理分支，不扩写成没有证据支持的原因。
- 默认不输出方案有效性免责声明，例如方案仅供参考、不能保证恢复等；直接列出具体复测项。
- 实际冲突和缺口必须按事实披露，例如 MF 方案与 Camera1 入口命名冲突、同对象配置值冲突、平台/版本不适用、候选通话日期尚未与本次投诉对应。必要条件未满足时仍按前表继续调查，不用来源标记跳过。
- 操作范围、顺序和限制是处理方案的一部分，必须保留；例如只排除问题设备、先排除全局命中再单机配置，不停用全局规则、不扩大到整个机型。
- 用户明确追问根因、版本依据、链接核验或方案效果时，按实际证据回答对应问题；不能为简化回复而声称未证实的事实。

### Event 证据

展示实际返回的事件名称、上海时间（含日期）、相关 UID、SID 前缀、相关详情字段及值。时间以本轮返回的权威时间字段转换，保留原始时间戳供内部追溯，不手算时区或混用秒/毫秒。ABTest 的 `params` 字符串先解析为 JSON，只展示目标键和值，不输出整份其他配置。区分“Event 已返回且无此键”和“Event 完全未返回”。配置存在的判断只依据该键和值；同一对象多条值冲突时展示时序与冲突，不能任选。

### Counter 和 VoQA 证据

展示实际 ID、名称、单位、方向或 peer、有效数据起止、有效/缺失点数、min/max、命中阈值的连续区间。必要时补平均值、零值比例和少量代表性原始点；不能只报平均值就称“持续异常”。单位为空就标“单位未返回”，不自行补百分比或 ms。没有定义“持续多久”或“波动多大”的阈值时如实给区间与波动，不创造阈值。

## 推荐配置如何写

给出目标 UID 对应的实际问题设备和单机范围，操作人执行前核对设备映射，不拿 UID 替代设备标识。入口直接取矩阵里当前分支的完整 URL；只能选相关配置，不列出所有候选制造歧义。机型级入口仅在用户明确要求且适用条件核实时给出。排除全局规则时仅排除目标设备，不能说“关闭全局配置”。

附件有准确键名的配置显示 JSON，例如软编、AGC 和 FFmpeg；没有准确键名的 Camera1/MF、Boost、AEC Filter、采集/播放增益、AirPlay 和 TCP Proxy 等，仅用矩阵里的操作名称、目标数值与入口，不自行编写私参。

无配置修改的已命中分支照样给必要证据、明确结论和“结论来自新东方专项SKILL。”，不强塞配置。有配置建议时说明“以上为推荐操作，本次未下发配置”。分支条件充分就直接给可执行方案，不反复用“可能需要调整”“建议进一步核实”弱化建议，不追加泛化免责声明。

### 内部判断约束（不作为命中回复的默认附加说明）

结论限定在专项实际支持的范围，不从调整建议倒推出未查到的现场状态或额外原因：不把 QP 高写成已确认硬编故障，不从 PC 和音量波动推定 AGC 为根因，不编造 Boost 开启状态，不从 FFmpeg=false 推定下载失败，不把 Scenario 当作当前系统音量类型的充分证明，不把重连推定为已确认的网络根因。AirPlay 按用户期望调整处理。配置入口未实际核验就不声称已核验，未执行或未复测就不声称已生效或已恢复。上述限制通过准确的结论和方案落实，无需逐条复制到回复；实际影响操作的冲突、缺口仍按前述规则披露。

## 默认附 Argus 链接

已经实际命中通话、验证目标 UID 存在于该通话用户会话时，即使专项条件未满足，也默认附人工复核链接。无需等待“Argus 发我”。链接格式固定为：

```text
https://argus.agoralab.co/call/qoe?id=<callId>&source=normal&rangeFromTs=<Unix秒>&rangeToTs=<Unix秒>&uids=<目标UID列表>
```

- `id` 只用真实 callId，不能把课程/教室 ID 或 SID 填进去。
- 链接时间默认取该通话真实 `createdTs/destroyedTs`，用带时区代码转换后列示上海时间；它不代表整通话都已分析。
- `uids` 仅含本轮该通话已验证的目标 UID，不能混入辅助 bucket、未匹配业务 ID、其他 callId 的 UID 或不相关用户。
- 同一 UID 多 callId 各生成一个链接，按真实开始时间列出。通话未结束时，结束时间使用本轮实际已校验查询窗结束，注明“仍在进行”；不能把 `destroyedTs=0` 当作 1970 年或擅自使用当前时间。
- 查询失败、通话未定位、UID 未匹配或时间不可验证时，不生成猜测链接；保留已查事实和缺口。
- URL 用标准库参数编码，绝不携带凭据。生成链接只代表人工入口，未实际打开不声称页面或内容已验证。

优先用本 Skill 的离线脚本生成：

```bash
python3 scripts/build_argus_links.py --calls /tmp/argus-calls.json --users /tmp/argus-users-by-call.json --uids 70000001 --output /tmp/argus-links.json
```

`--calls` 接受 `argus_rest.py` 保存的成功 get-call 或 search-calls 包装结果；`--users` 是以真实 callId 为键、各自完整 search-users 包装结果为值的 JSON 对象。保留这些包装的 `request.path`，脚本校验用户结果来自对应通话。只读本地文件、不请求后台。`--uids` 为精确目标 UID，必须在每个要生成链接的通话结果中均匹配；不匹配时显式失败，不静默跳过。只为部分候选生成时，先用文件工具筛出已核验目标通话结果。

对仍在进行的通话，用户结果中的 `request.query.toTs` 必须是有效、已校验的本轮查询结束；脚本使用该值。实际 get-call 的生命周期若尚未获取，应先通过公共 Argus Skill 取回；不要为生成 URL 伪造输入。
